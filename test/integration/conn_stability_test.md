# 连接稳定性手动验证脚本

本文档列出 5 个手测场景，必须在主要里程碑（P0、P1、自适应工作完成时）回归。

## 前置

- 一台真机（Android），装上对应 build APK
- 服务端为本机或可控测试服务器
- Settings 中开启调试面板（连点版本号 7 次）

## 场景 1：稳态打字 5 分钟（验稳定）

1. 打开 mosh+tmux+claude tab
2. 持续打字 / 让 claude 生成回复（5 分钟）
3. 观察调试面板：
   - `stab` 应稳定在 90-100
   - `rc` 应保持 0
   - 不应出现 `[重连中...]` banner
4. 通过条件：5 分钟内 0 次 reconnect

## 场景 2：飞行模式 5 秒（验真断恢复）

1. 打开 mosh+tmux+claude tab，让 claude 在跑
2. 切到飞行模式开关，关 5 秒，再打开
3. 观察重连过程
4. 通过条件：
   - 30 秒内出现 "[Mosh 会话已恢复]" banner
   - 不出现 "server exited unexpectedly"
   - tmux session 仍在跑（回到 claude 界面）

## 场景 3：弱网持续 10 分钟（验 cascade 守门）

1. 站到 WiFi 信号边缘 / 用网络受限工具
2. 让连接持续抖动 10 分钟
3. 观察调试面板 `rc` 字段
4. 通过条件：
   - reconnect 次数 ≤ 1（cascade guard 阻止 storm）
   - 若触发冷却，应看到 "[网络不稳定，30s 后重试]" banner

## 场景 4：后台 1 小时切回（验长空闲恢复）

1. 打开 mosh tab 后切到桌面 / 锁屏
2. 等 1 小时（或 30 分钟以上）
3. 切回 app
4. 通过条件：
   - 30 秒内确认状态：要么显示已恢复，要么进入 reconnect 流程
   - 30 秒后必有明确反馈，不应卡在"假装连着"状态

## 场景 5：纯 SSH 连接的死亡检测（验 keepalive）

1. 开纯 SSH（关 mosh）tab，连接到测试服务器
2. 在服务端用 `iptables -A INPUT -p tcp --dport 22 -j DROP` 模拟连接死亡
3. 观察检测时间
4. 通过条件：
   - 13 秒内（8s keepalive + 5s poll）显示 "[重新连接中...]"
